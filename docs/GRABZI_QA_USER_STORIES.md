## 1. Обзор, домены и доступы

GRABZI — сервис предзаказа и выдачи напитков drive-through (выдача по номеру авто). Три части:

| Часть | Что | Прод-домен | Локально |
|---|---|---|---|
| **grabzi-web** | Публичный сайт заказа (актуальный фронт) | `https://grabzi.mediann.dev` | `:3001` |
| **app/** | Полная админка (управление) | `https://admin.grabzi.mediann.dev` | `:3000` |
| **backend** | FastAPI + SQLite | `https://api.grabzi.mediann.dev` | `:8000` |

Оба фронта обращаются к общему бэкенду по `https://api.grabzi.mediann.dev`. Бариста-экран есть и в
grabzi-web (`/admin/kitchen`), и полноценная админка — в `app/`.

**Доступы в админку (сид по умолчанию):**

| Роль | Email | Пароль | Куда ведёт после логина |
|---|---|---|---|
| Супер-админ | `admin@juicy.ae` | `admin123` | `/admin` (дашборд, всё) |
| Менеджер | `manager@juicy.ae` | `manager123` | `/admin/orders` (только свои точки) |
| Экран выдачи | `screen@juicy.ae` | `screen123` | `/admin/screen` (read-only) |

**Легенда статусов точки** (приоритет сверху вниз):
`inactive` (выключена) → `closed` (вне часов) → `paused` (ручная пауза или лимит) → `open` (принимает заказы).

**Семантика часов работы:** ключи дней — строки **«0»–«6» (Пн=0)**; пустой объект `hours = {}` = **круглосуточно (24/7)**, а не «закрыто».

**Лимит:** дневной лимит напитков считается **только по оплаченным** заказам (по количеству), авто-пауза при достижении, сброс в локальную полночь точки.

## 2. Акторы (роли)

| Актор | Где работает | Что делает |
|---|---|---|
| **Гость / Клиент** | grabzi-web (публичный) | смотрит лимит/точки/меню, заказывает, платит, отслеживает статус, «I'm here», история заказов |
| **Бариста (manager)** | grabzi-web `/admin/kitchen` + app `/admin/orders` | принимает заказ (take), готовит (ready), выдаёт (completed); видит только свои точки |

| **Менеджер (admin)** | app `/admin/*` | заказы, детали, статусы, рефанд; только назначенные точки |
| **Супер-админ** | app `/admin/*` | всё: точки, каталог, клиенты, стафф, платежи, дашборд, аудитория, экспорты |

## 4. Критерии приёмки (Given/When/Then)

> Ключевые проверяемые критерии. Полный список флоу — в разделе 5. Коды ошибок — в разделе 9.

### 4.1 Клиент: заказ и оплата

- **WEB-1 · TODAY'S LIMIT.** GIVEN открыта главная · WHEN страница загрузилась · THEN: 1 точка → крупно `«sold / limit»`; 0 точек → `«—»`; **2+ точек → сетка с именем каждой точки + `sold/limit` + прогресс-бар** (ревалидация кэша каждые 30с).
- **WEB-2 · Статус точки.** THEN бейдж: `paused`→«Paused — not taking orders»; `closed`→«Closed — opens HH:MM» (или «Closed now»); sold-out→«Sold out — back HH:MM/tomorrow» + лента **SOLD OUT**; иначе «Plenty left / Selling fast / Almost gone». Заказ доступен только при `acceptingOrders=true`.
- **WEB-3 · Маски и валидация.** Телефон `50123456`→`+971 50 123 4567` (на бэк `+9715XXXXXXXX`); номер авто `ab12345`→`A 12345` (0–2 буквы + до 5 цифр); пустые поля при submit → инлайн-ошибки под каждым полем (не модалка), ошибка очищается при вводе.
- **WEB-3 · Гард по остатку.** GIVEN `remaining=5`, в корзине 7 · WHEN «Proceed to Payment» · THEN модалка «Only 5 left here. Reduce your order.».
- **WEB-4 · Checkout.** WHEN валидные данные · THEN авто-логин (без OTP) → `createOrder` (outletId, items с `addons:[]`, carPlate, customerName) → checkout. `mock=true`→редирект `/orders/[id]?paid=1`; иначе → Stripe URL. Токен в localStorage.
- **WEB-5 · Трекинг.** THEN WS `/ws/orders/{id}?token=…`; при сбое — polling каждые 20с. Степпер Received→Making→Ready→Handed over; бейдж «Payment pending» при `paymentStatus!=paid` (не скрывает степпер); кнопка «I'm here» при `paid && !arrived`; `refund` → степпер не рендерится.

### 4.2 Бариста / Экран / Безопасность

- **AUTH-1.** Верные креды → токен в localStorage (`grabzi_staff_token`), редирект по роли (manager→orders, screen→screen). Неверный пароль → «Wrong email or password». `disabled=true` → 401.
- **KIT-2/3/4.** TAKE: `new→in_progress` (+ `manager_id`, событие). READY: `in_progress→ready`. HANDED OVER: `ready→completed`. Невалидный переход (напр. `new→completed`) → **409 INVALID_TRANSITION**.
- **KIT-5.** `limit=100, sold=75`→«75/100 · 25 left», бар 75%; `100/100`→бар красный; `limit=null`→«Sold 47 · No limit» без бара.
- **SEC-1.** Manager видит только свои точки; чужой заказ по ID → **404** (не 403). Super-admin — все.
- **SEC-2.** Screen POST `/take` или `/status` → **403 FORBIDDEN**.

### 4.3 Точки (admin + backend)

- **OS-003.** Выключить последнюю активную → **409 LAST_ACTIVE_OUTLET**. При 2 активных — выключение проходит (200).
- **OS-006.** Save часов: `{'0': [], '1': [{open:'00:00',close:'24:00'}], '2': [{open:'09:00',close:'21:00'}]}` — `[]`=закрыто, `00:00–24:00`=24/7, иначе по времени. `close ≤ open` → **422 OUTLET_HOURS_INVALID**.
- **OS-007.** `hours={}` → на публичке «Open 24/7», заказы в любое время.
- **OS-009.** При оплате, доводящей до лимита, `auto_paused=true` + событие `limit_reached`, статус `paused (paused_limit)`. Счётчик — **только paid**.
- **OS-013.** Screen при привязке ко 2-й точке — перемещается (ровно 1). Отвязать последнюю точку у manager/screen → **409 STAFF_NEEDS_OUTLET**. Супер-админ не привязывается.
- **OS-015 / backend.** Создание заказа при статусе ≠ `open` → **409 OUTLET_CLOSED**.

### 4.4 Каталог

- **ADM-S-05.** Размеры: ≥1 активный; volume>0, price≥0; ровно один default; иначе ошибка (или **422 PORTIONS_RANGE_INVALID**). Привязки: `0 ≤ min ≤ default ≤ max`, portion>0. Описание санитизируется (только h2/h3/b/strong/i/em/u/p/br/ul/ol/li).
- **ADM-S-11.** Пустой AR-перевод → оранжевый бейдж «★ no AR» + подсветка поля.
- **i18n.** Имя на публичке: `en ?? ru` (англ. первым). Проверить единообразие во всех местах (см. bug-watch).

### 4.5 Backend — правила заказа и роли (коды ошибок)

| Сценарий | Условие | Ответ |
|---|---|---|
| Пустая корзина | `items=[]` | 422 `CART_EMPTY` |
| Нет номера авто | `car_plate` пуст (и в профиле) | 422 `CAR_PLATE_REQUIRED` |
| Точка не open | вне часов / пауза / лимит / inactive | 409 `OUTLET_CLOSED` |
| Напиток недоступен | не published / в стоп-листе / категория в стоп-листе | 409 `DRINK_NOT_AVAILABLE` |
| Добавка в стоп-листе | addon в `stop_items` | 409 `ADDON_NOT_AVAILABLE` |
| Несколько активных, нет outletId | 2+ active | 422 `OUTLET_REQUIRED` |
| Повторная оплата | `payment_status=paid` | 409 `ALREADY_PAID` |
| Повторный рейтинг | rating уже задан | 409 `ALREADY_RATED` |
| Купон чужой/неактивный | | 409 `COUPON_INVALID` |
| Купон уже зарезервирован | в неоплаченном заказе | 409 `COUPON_ALREADY_RESERVED` |
| Take неоплаченного | `payment_status!=paid` | 409 `ORDER_NOT_PAID` |
| Само-демоут/disable | super-admin сам себя | 409 `CANNOT_DEMOTE_SELF` / `CANNOT_DISABLE_SELF` |

### 4.6 SEO / realtime / состояние

- **SEO-01.** Несуществующий публичный URL → **HTTP 404** (не 200) + `meta robots noindex`.
- **SEO-02.** `admin.grabzi.mediann.dev` и `api.grabzi.mediann.dev` → заголовок `X-Robots-Tag: noindex`; у API ещё и `/robots.txt` Disallow.
- **REALTIME-01.** WS отдаёт апдейт ≤100мс; при сбое — polling 20с; сообщения `type:'ping'` игнорируются.
- **AUTH-01 (WS).** Невалидный/просроченный токен → `close(1008)`; клиент B не может смотреть заказ клиента A.
- **STATE-01/03.** Профиль/корзина персистятся (Zustand+localStorage, миграция схемы). Неоплаченный заказ — бейдж «Payment pending» **не скрывает** степпер; `refund` — степпер скрыт.

## 5. Сквозные QA-флоу (walkthroughs)

> Прогоняем руками. Слева — действие, справа — ожидаемый результат.

### 5.1 Клиент: заказ от и до (happy path)

1. Открыть `grabzi.mediann.dev` → главная: лого, бегущая полоска, **TODAY'S LIMIT** (по каждой точке), слоган, футер со ссылками Menu / Hours & contact.
2. «ORDER NOW» → `/locations`: заголовок «CHOOSE YOUR SPOT», карточки точек: имя+адрес, **LEFT TODAY** с баром, статус-точка+сообщение, лента SOLD OUT (если 0), «Today HH:MM» + «All hours».
3. «All hours» → раскрытие недели (сгруппировано: «Mon–Fri 09:00–22:00», «Sat–Sun Closed/24h»).
4. Тап по карточке → `/order`: вверху карточка точки (статус, LEFT TODAY, часы, «Change»).
5. «Change» → список других точек со статусом → выбор → перезагрузка напитков новой точки.
6. Список напитков: имя+цена, степпер; sold-out — бейдж, без степпера.
7. «+» ×3 → 0→1→2→3 (пружинка на числе).
8. Собрать корзину (2×A 100 + 1×B 50) → кнопка «Proceed to Payment · AED 250».
9. Имя/телефон/авто; пустые → инлайн-ошибки; гард по остатку — модалка.
10. Submit → авто-логин → создание → checkout. mock → `/orders/[id]?paid=1`.
11. На `/orders/[id]`: номер, сумма, позиции, точка, степпер, бейдж оплаты, статус-копирайт.
12. WS/poll двигает статус new→in_progress (степпер обновляется без перезагрузки).
13. При `paid && ready` → «I'm here» → POST `/arrived` → «We know you're here».
14. `/orders` без токена → форма входа по телефону; вход без OTP; список заказов (номер/время/статус/позиции/точка/оплата/сумма).
15. `/menu` → `/product/[slug]`; `/info` (контакты + OUR SPOTS); `/no-such` → брендовая **404 (статус 404)**.

### 5.2 Бариста / Экран

1. `admin.grabzi.mediann.dev/admin/login` → manager → `/admin/orders` (и `/admin/kitchen`).
2. Канбан: NEW / MAKING / READY·HANDOUT / DONE; шапка точки + «Sold X/Limit». WS в фоне.
3. Клиент создаёт оплаченный заказ → появляется в NEW за 1–2с (WS) или ≤10с (poll).
4. TAKE ▶ → MAKING, таймер пошёл. READY ✓ → READY·HANDOUT. HANDED OVER ✓ → DONE (исчезает).
5. Флаг «arrived» — рамка карточки выделена («🚗 HERE»).
6. Экран (`screen@juicy.ae`) → `/admin/screen`: две секции; READY на кухне → realtime в «Ready» на экране; HANDED OVER → исчезает.
7. Screen POST `/take` → **403**. Manager видит только свои точки (чужой заказ → 404).

### 5.3 Менеджер / Супер-админ (app/)

1. Супер-админ → `/admin` (дашборд: KPI, периоды today/7d/30d/custom, фильтр точки, графики, экспорт .xlsx).
2. `/admin/orders` → take/open/ready/handed over/refund; деталь с таймлайном и кликабельными именами стаффа.
3. `/admin/outlets` → список со статусами; деталь, вкладки **Основное / Расписание / Сотрудники / Меню точки / История**:
   - Расписание: 3 режима/день; пустое = 24/7; `close≤open` → 422.
   - Лимит: ввод → авто-пауза при достижении (paid-only) → «resets at 00:00» в TZ точки.
   - Меню точки: стоп-лист (мгновенный toggle) + приоритеты (sort/pin, по «Save priorities»).
   - Сотрудники: attach manager/screen (screen — ровно 1 точка), 409 при отвязке последней.
   - История: аудит всех изменений.
4. `/admin/catalog/*`: напитки (draft→published), размеры, привязки добавок, описание EN/AR, категории, добавки/единицы.
5. `/admin/customers` (сортируемый, деталь RFM/CLV), `/admin/payments` (рефанд), `/admin/audience` (сегменты), `/admin/staff` (CRUD + роли).
6. Менеджер: `/admin/customers` → **403**; видит только свои точки. Screen: read-only.

## 8. Финальный QA-чеклист

> End-to-end проверки максимальной ценности. Отмечать `[x]` по мере прохождения.

- [ ] **Lifecycle + выключение точки:** заказ на активной точке → выключить точку посреди флоу → submit даёт 409 OUTLET_CLOSED, понятная ошибка, корзина сохранилась
- [ ] **Параллельные заказы на границе лимита:** `limit=5, sold=4`, 2 таба, submit одновременно → один проходит, второй видит «Only X left», auto_paused ровно один раз (одно событие в аудите)
- [ ] **Корзина после смены точки:** товар на т.A → «Change» на т.B → корзина пуста/перевалидирована, старые drinkId не уходят; если уходят — 409 с понятной ошибкой
- [ ] **Протухший токен на трекинге:** `/orders/[id]`, часы +25ч, апдейт статуса → «Session expired»/редирект (WS закрыт, polling 401)
- [ ] **Гонка стоп-листа:** открыт `/order` → админ стопит напиток → клиент добавляет → submit 409 DRINK_NOT_AVAILABLE, понятно
- [ ] **Пауза/возобновление при активной кухне:** заказ в MAKING → пауза точки → баннер «paused», существующие заказы видны/кликабельны, новые не создаются
- [ ] **Manager отключён в сессии:** disable → следующий вызов 401 → редирект на логин (не «протухшая» доска)
- [ ] **Анти-дабл купона:** заказ#1 с купоном (pending) → назад на `/order` → снова submit → 409 COUPON_ALREADY_RESERVED с понятным сообщением
- [ ] **WS fallback polling:** `/orders/[id]` на Slow 3G → апдейт статуса → UI обновился ≤10с, без дублей
- [ ] **Отображение refund:** заказ → completed → рефанд → клиентская `/orders/[id]` показывает refund-состояние (не сломанный степпер)
- [ ] **Маска авто:** `AB12345XYZ`→`AB 12345`; 3 буквы/символы отклонены; пробел авто-вставляется
- [ ] **Маска/нормализация телефона:** `+971 50 …`, `050…`, `971…` → один канонический `+9715XXXXXXXX`; `<9` цифр → невалидно
- [ ] **Сброс лимита в полночь TZ:** TZ='Asia/Dubai', `limit=10, sold=10, auto_paused`; в 23:50 — нет сброса; в 00:05 след. дня — `auto_paused=false`, счётчик 0
- [ ] **Мульти-точка:** 2+ активных → на `/locations` все, на `/order` «Change»; смена перезагружает меню, корзина не чистится; outletId уходит в API
- [ ] **Атомарность номера заказа:** 10 параллельных POST `/api/orders` → уникальные номера, без 409/пропусков
- [ ] **Выключенная точка:** скрыта на публичке (`active=false`), но существующие заказы видны на кухне; супер-админ видит её в списке
- [ ] **«I'm here» идемпотентность:** повтор тапа → нет двойного события
- [ ] **Soft-404 продукта:** `/product/nonexistent` рендерит, статус (200 — по дизайну), meta robots=noindex
- [ ] **Пустое расписание = 24/7:** `hours={}` → «Open 24/7», заказы в любое время; `{0:[],…}` → «closed»
- [ ] **Sold-out точка:** `remaining=0` → лента SOLD OUT, бар 100%, статус «Sold out — back …», «ORDER» disabled
- [ ] **SEO noindex:** `curl -i` admin/api → `X-Robots-Tag: noindex`; публичная 404 → HTTP 404 + meta noindex

- [ ] **Logout чистит токен:** после logout `grabzi_staff_token` удалён (нет авто-входа)
