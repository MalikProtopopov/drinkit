## Часть 1. Что улучшено и как

| Коммит | Область | Переносится на jooz-main? |
|---|---|---|
| `61391a1` | **backend** (FastAPI) — безопасность, конкурентность, рефанд, прочее | ✅ да |
| `8f62d46` | **app/ admin** — каталог, i18n, рефанд-клиент, экспорт, дашборд, 401 | ✅ да (только админка; 1 адаптация) |
| `976e089` | **grabzi-web** — публичный сайт GRABZI | ❌ нет (на jooz-main нет `grabzi-web`; публичный сайт не трогаем) |
| `31f38a3` | docs (QA §10) | ⚪ опционально |
| `7fe8b34`,`accee82` | deploy (Makefile, multi-stage Docker) | ❌ нет (завязано на `grabzi-web`; у jooz свой деплой) |

### 1.1 Backend (`61391a1`) — все файлы есть и на jooz-main

**Безопасность**
- **JWT-секрет**: `_guard_prod_secrets()` в `main.py` — падаем на старте, если в проде (не-SQLite) остался дефолт `dev-secret-change-me`.
- **OTP**: `otp_dev_mode` по умолчанию **False** (`config.py`); в `auth.py` — антифлуд `OTP_RATE_LIMITED` + инвалидация прежних кодов при перезапросе.
- **WS-скоуп**: `ws.py` `_can_watch_order` — персонал видит заказ только своей точки (super_admin — любой).
- **Валидация привязок**: `admin_catalog.py` `BindingIn` — `portionAmount > 0`, `priceOverride ≥ 0`.

**Конкурентность** (Postgres `FOR UPDATE` / на SQLite запись и так сериализована)
- `order_flow.py`: номер заказа — retry на `IntegrityError` вместо 500; резерв купона — `with_for_update`; `limit_reached` срабатывает один раз (лок точки в `mark_paid`); лимит остаётся «мягким».
- `admin_outlets.py`: деактивация точки — лок строк активных точек (нельзя обнулить число активных гонкой).

**Рефанд**
- `admin_orders.py`: order-рефанд проставляет `refunded_amount` (чинит завышенный net), проверки статуса/оплаты до мутаций, **обязательная причина** (`reason`), сброс `auto_paused` после возврата (O5).
- `admin_payments.py`: атрибуция актора в событии возврата, сброс `auto_paused` при полном возврате.
- `order_flow.py`: гард на отсутствующий купон в `mark_paid` (PAY-500).

**Прочее**
- `admin_exports.py`: `customers.xlsx` учитывает sort/dir/поиск.
- `crm_rfm.py`: убраны недостижимые ветки сегментации.
- `catalog.py`: публичный `/api/drinks?outletId=` применяет стоп-лист точки (**обратно совместимо** — без параметра поведение прежнее).
- Тесты: `conftest.py` (OTP dev в тест-окружении), рефанд-тесты под обязательный reason, новые тесты валидации привязок.

### 1.2 app/ admin (`8f62d46`) — только админ-файлы (6), публичных нет

- `catalog/products/[slug]/page.tsx`: `basePrice` синкается сразу при смене default-размера (CAT2).
- `components/admin/product-editor/ProductBindingsTab.tsx`: добавки из выключенной категории скрыты в билдере (CAT5).
- `catalog/groups/page.tsx`: имена add-on категорий/единиц — EN-first + бейдж «no AR» + поля AR ⚠️ **(на jooz-main адаптировать под RU-first, см. §2.4)**.
- `lib/adminApi.ts`: `refund(id, reason)` шлёт обязательную причину; глобальная обработка **401 → редирект на /admin/login**.
- `customers/page.tsx`: экспорт клиентов несёт активные sort/dir.
- `admin/page.tsx`: кастомный период дашборда считается в TZ точки (Dubai +04:00); Peak hour «—» на пустом периоде.

### 1.3 grabzi-web (`976e089`) — НЕ переносится

Публичный сайт GRABZI (корзина/стоп-лист, 404 продукта, TZ часов, трекинг, кухня и т.д.).
На jooz-main каталога `grabzi-web` нет, а **публичный сайт jooz-main трогать нельзя** — этот коммит исключаем целиком. Эквивалентные баги в публичной части `app/` на jooz-main по решению владельца **не чиним**.

## Часть 2. План переноса на jooz-main (без публичного сайта)

### 2.1 Факты о ветке (проверено)
- `jooz-main` **не содержит** `grabzi-web`; публичный сайт живёт внутри `app/` (оригинальный JOOZ = публичная часть + админка).
- Общий предок веток: `2c1df80`.
- Все изменённые мной **backend-файлы существуют** на jooz-main и структурно совпадают (мульти-точка тоже есть) → backend-правки портируемы целиком.
- Админ-код jooz-main **почти идентичен** grabzi-main до правок: `adminApi.refund(id, note)` тот же; экран заказа **уже** собирает обязательную причину (`refundReason`, `disabled={!refundReason.trim()}`, `adminApi.refund(order.id, refundReason.trim())`); дашборд с тем же багом дат; groups — RU-first.

### 2.2 Что переносим / что не трогаем

| Область | Действие | Почему |
|---|---|---|
| backend (`61391a1`) | **Перенести** | Общий бэкенд; публичный API меняется только обратно-совместимо |
| app/ admin (`8f62d46`) | **Перенести** (только эти 6 файлов) | Чисто админка, публичных файлов не касается |
| `app/app/admin/catalog/groups/page.tsx` | Перенести **с адаптацией** | jooz RU-first (§2.4) |
| Публичные роуты `app/` (не `/admin`), `app/lib/api.ts` | **НЕ трогать** | Это публичный сайт jooz-main |
| grabzi-web (`976e089`), deploy (`7fe8b34`,`accee82`) | **Пропустить** | Нет на jooz-main / завязано на GRABZI |
| docs (`31f38a3`) | Опционально | Документация |

### 2.3 Механика — cherry-pick двух коммитов

```sh
git fetch origin
git switch jooz-main && git pull --ff-only

# 1) Бэкенд (файлы те же, ожидается чисто или с тривиальными конфликтами)
git cherry-pick 61391a1
#   при конфликте: git status → разрулить → git add -u backend && git cherry-pick --continue

# 2) Админка БЕЗ автокоммита — чтобы поправить i18n до фиксации
git cherry-pick -n 8f62d46
#   адаптировать groups (см. §2.4), затем:
git add -u app && git commit -m "fix(admin): catalog sync, refund reason, export filters, dashboard TZ, 401 (port from grabzi-main)"
```

> `cherry-pick -n` для админки даёт возможность отредактировать `groups/page.tsx` под RU-first
> прежде, чем коммитить. Бэкенд можно обычным cherry-pick.

### 2.4 Адаптации

1. **i18n groups (обязательно).** Моя правка делает отображение `en ?? ru` (EN-first) и шлёт `ar`.
   На jooz-main аудитория RU → в `catalog/groups/page.tsx` поставить порядок **`ru ?? en ?? "—"`**
   для категорий и единиц; поля AR можно оставить (полезно), но проверить, что create-модалка
   создаёт запись с тем ключом, который потом показывается (иначе вернётся баг пустых имён).
2. **Дашборд TZ.** Фикс жёстко берёт `+04:00` (Dubai). JOOZ тоже ОАЭ → подходит. Если у jooz
   точки в иной TZ — заменить смещение/брать из точки.
3. **Рефанд — связка уже целая.** Экран заказа jooz **уже** требует причину и передаёт её, поэтому
   после переноса backend (reason обязателен) + `adminApi.refund(id, reason)` всё сходится; UI править НЕ нужно.
4. **catalog.py `outletId`.** Параметр опционален; публичный сайт jooz его не передаёт → поведение
   витрины не меняется. Трогать публичный фронт не требуется.

### 2.5 Верификация (на jooz-main)

```sh
# backend — весь набор тестов должен быть зелёным
cd backend && source .venv/bin/activate && python -m pytest -q

# фронт-админка типобезопасна
cd app && npx tsc --noEmit

# ГЛАВНОЕ: публичный сайт не затронут — в диффе переноса не должно быть НИ ОДНОГО
# публичного файла app/ (всё под app/app/admin, app/components/admin, app/lib/adminApi.ts):
git diff --name-only 2c1df80..HEAD -- app | grep -vE '^app/(app/admin/|components/admin/|lib/adminApi\.ts)' || echo "OK: публичных файлов app/ не тронуто"
```

Дополнительно проверить смоук: вход в админку, рефанд с причиной (200) и без (422), экспорт клиентов с сортировкой, дашборд за кастомный период.

### 2.6 Откат
Каждый шаг — отдельный коммит: `git revert <hash>` откатывает область независимо. До пуша —
`git reset --hard origin/jooz-main`. Бэкенд и админка изолированы, публичный сайт не участвует.
