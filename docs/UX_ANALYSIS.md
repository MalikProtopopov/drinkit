# UX-аудит и редизайн — экран управления точкой (super-admin)

> Скоуп: `app/app/admin/outlets/page.tsx` (список) и `app/app/admin/outlets/[id]/page.tsx`
> (карточка точки, вкладки Основное / Расписание / Сотрудники / Меню точки / История).
> Цель: сделать понятнее и **защитить супер-админа от ошибок** при управлении локацией.
> Метод: разбор кода + знание бэкенд-семантики `[по коду]` (живой клик в браузере не выполнялся).
> Бэкенд-инварианты, против которых меряем: последнюю активную точку выключить нельзя (409);
> 2-я активная требует `force`; дневной счётчик paid-only авто-паузит; пустые `hours {}` = 24/7.

## 1. Резюме

Функционально вкладка закрывает все требования, но **ментальная модель состояния точки сломана**:
четыре независимых «выключателя» (мастер-флаг, ручная пауза, расписание, дневной лимит) схлопнуты в
**одну пилюлю статуса, которая не объясняет ни ПОЧЕМУ точка в этом состоянии, ни КАК это починить**.
Главный риск ошибок супер-админа: он не различает «выключить точку насовсем» / «пауза на час» /
«закрыто по часам» / «упёрлись в лимит» — и совершает не то действие.

Светофор по под-флоу:

| Флоу | Статус | Одной фразой |
|---|---|---|
| Создать / включить / выключить точку | 🟡 | защита от «последней активной» есть, но статус не объясняет состояние |
| Понять «почему точка не принимает заказы» | ❌ | пилюля без причины; микрокопия про авто-паузу **врёт** (F3) |
| Поставить точку на паузу вручную | ❌ | контрола нет вообще — бэк умеет, UI нет (F2) |
| Настроить расписание | 🟢 | режимы Закрыто/24ч/Время понятны; нет сводки/пометки «не задано» |
| Стоп-лист и приоритеты | 🟡 | часть сохраняется мгновенно, часть по кнопке (рассинхрон, F6); приоритеты числами (F7) |
| История изменений | ❌ | сырой enum, без «было→стало» и без автора — для аудита бесполезна (F8) |

Метрики сейчас (для экрана): **11 полей** свалены в одну форму «Основное» без группировки;
**4** разных состояния-выключателя без единой модели; **1** мгновенно дезинформирующая надпись;
кликов «понять почему точка на паузе» → **∞** (из UI не выводится).

## 4. Карта состояний (откуда берётся пилюля)

```
                       ┌─────────────────────────────────────────────┐
 is_active = false ───▶│ INACTIVE  (точка выключена супер-админом)     │  🔴
                       └─────────────────────────────────────────────┘
        │ true
        ▼
 вне рабочих часов  ───▶  CLOSED   (по расписанию)                        🟡
        │ в часах (или hours={}=24/7)
        ▼
 accepting_orders=false ─▶ PAUSED  (ручная пауза)                        🟡
        │ true
        ▼
 лимит достигнут (paid≥limit) ─▶ PAUSED (упёрлись в дневной лимит)        🟡
        │ нет
        ▼
                          OPEN     (принимает заказы)                    🟢
```
**Проблема:** UI показывает только финальную метку (open/paused/closed/inactive) и **теряет ветку,
которая её вызвала**. Два разных «paused» (ручной и лимитный) и «closed» неотличимы для админа.

## 6. Пробелы покрытия (бэк есть — фронта нет)

- **Ручная пауза `accepting_orders`** — эндпоинт `PATCH {acceptingOrders}` реализован, но в UI только текст. Супер-админ физически не может «остановить приём на час» (F2).
- **`outlet_events.meta`** — бэк пишет богатый payload (старые/новые часы, лимит, какой напиток застопили, счётчик при limit_reached), но фронт History рендерит только `type`+`note` (F8).
- **Причина статуса** — бэк знает ветку (inactive/closed/paused-manual/paused-limit), фронт схлопывает в одну метку (F3).

## 7. Дизайн-направление (north-star)

**«Светофор с причиной и одной кнопкой-исправлением».** Супер-админ за 2 секунды видит: работает ли
точка, почему, и что нажать, чтобы изменить. Сложность четырёх флагов несёт **система**, а не человек.

Опорные принципы:
- **Видимость статуса (Нильсен #1) + Помощь при ошибке (#9):** статус всегда с причиной и действием.
- **Профилактика ошибок (#5) > запреты:** подтверждение + «было→стало» на операционных изменениях; не дать ввести мусор.
- **Закон Теслера:** 4 механизма «не принимает заказы» система объясняет сама; админ не держит их в голове.
- **Хик/Миллер:** форму бьём на 3–4 смысловые карточки; на экране одно главное действие.
- **Узнавание, не вспоминание (#6):** порядок напитков — перетаскиванием, таймзона — выбором, не вводом.
- Эталоны: Stripe (статус-баннер аккаунта с причиной и CTA), Shopify/Square (карточка локации: «Open · closes 10 PM», ручная пауза «Pause online ordering»), Linear (история с диффами).

## 8. Редизайн ключевых узлов (before → after)

### 8.1 Блок статуса — ядро (решает F3, F4, F13, частично F8)

Вынести **над табами** единый «статус-баннер» с цветом, человеческой причиной и кнопкой-исправлением.

СЕЙЧАС: пилюля «пауза» в двух местах, причина не видна, надпись про авто-паузу врёт.

ПРЕДЛАГАЮ:
```
┌────────────────────────────────────────────────────────────────────────┐
│  JOOZ Главная                                          [⚙ Основное ▸]    │
│  🟡  На паузе — достигнут дневной лимит (200/200)                          │
│       Приём возобновится автоматически в 00:00 (Asia/Dubai)              │
│                                          [Поднять лимит]  [Снять паузу]   │  ← кнопки зависят от причины
└────────────────────────────────────────────────────────────────────────┘
```
Варианты причины (одна строка + правильное действие):
- 🟢 **Открыта** — «принимает заказы · сегодня до 22:30» (или «круглосуточно» / «расписание не задано — работает всегда»).
- 🟡 **Пауза (вручную)** — «приём остановлен супер-админом» → [Возобновить приём].
- 🟡 **Пауза (лимит)** — «достигнут лимит 200/200, сбросится в 00:00» → [Поднять лимит].
- 🟡 **Закрыта** — «вне рабочих часов · откроется завтра в 07:00» → [Изменить расписание].
- 🔴 **Выключена** — «точка отключена» → [Включить точку].

Почему проще: один источник статуса (минус дубль F4), причина = закон #1/#9, кнопка-исправление = «один
очевидный следующий шаг» (минус тупик F13). Требует на бэке отдать **причину** (`statusReason:
'inactive'|'closed'|'paused_manual'|'paused_limit'|'open'`) + `opensAt`/`resetsAt` — это +1 поле в
сериализаторе `_row`, статус-машина уже всё знает.

### 8.2 Разделить «насовсем» и «прямо сейчас» (решает F2, F13)

Переименовать и разнести два уровня, чтобы «выключить» ≠ «пауза»:
```
Доступность точки
┌─────────────────────────────┐   ┌─────────────────────────────────────┐
│ Точка включена      [ ✔ ]   │   │ Приём заказов сейчас      [ ✔ ]      │
│ Выключенная не видна на      │   │ Временная пауза, не трогает          │
│ сайте и не принимает заказы  │   │ расписание. [на 1 час][до утра][∞]   │
│ (последнюю выключить нельзя) │   └─────────────────────────────────────┘
└─────────────────────────────┘
```
Левый — мастер (`is_active`, с подтверждением, защита последней активной). Правый — **новый**
переключатель ручной паузы (`accepting_orders`), которого сейчас нет. Пресеты «на 1 час/до утра» —
nice-to-have (можно позже хранить `paused_until`); минимально — простой toggle.
Почему проще: разные слова для разных понятий убирают путаницу «выключить vs пауза vs закрыто».

### 8.3 Форму «Основное» — в карточки (решает F5, F10, F13)
```
[ Профиль ]            названия RU/EN/AR · адрес · эмират · телефон · email
[ На карте ]           lat · lng  → мини-превью карты / «Открыть ↗»
[ Операционные правила] Дневной лимит [____] напитков (пусто = без лимита)
                        рядом живой счётчик: «сегодня 187»  ·  Таймзона [Asia/Dubai ▾ select]
```
Лимит — в отдельную карточку рядом со счётчиком (видна связь), таймзона — **select** из списка IANA
(не свободный текст), числа — с валидацией (целое ≥ 0; NaN не уходит). Почему проще: Хик/Миллер
(чанки), операционно-опасное поле визуально отделено от косметики.

### 8.4 Меню точки: единая модель + сводка (решает F6, F7)
- Сверху — сводка: **«Скрыто на точке: 3 напитка · 1 категория · 2 добавки»** + [Очистить стоп-лист].
- Стоп-тоглы остаются мгновенными (это «есть/нет в наличии») — но с тостом-подтверждением.
- Приоритеты — **перетаскиваемый список** «Порядок в меню точки» с ⭐-закрепить, вместо ручного ввода
  чисел по 28 строкам. Сохранение — единым «Применить порядок» (или авто). Убрать рассинхрон: либо всё
  авто, либо всё по кнопке — выбрать одно (рекоменд.: стоп — авто, порядок — drag + автосейв).

### 8.5 История: по-человечески (решает F8)
```
Сегодня 14:32  ·  Малик (супер-админ)   Достигнут дневной лимит      200 из 200
Сегодня 09:10  ·  Малик                 Изменено расписание          Пн: 07:00–22:30 → круглосуточно
Вчера 18:40    ·  система               Стоп-лист: скрыт напиток      «Морковный фреш»
```
Маппинг `type` → русская фраза, `meta` → «было → стало», `by_staff_id` → имя (или «система»).
Эндпоинт `events` уже отдаёт `meta` и `byStaffId` — нужен только маппинг на фронте.

## 9. Что убрать / слить / отложить (лог вычитания)

| Элемент | Действие | Почему проще |
|---|---|---|
| Дубль статус-пилюли (таб-бар + панель) | **слить** в один баннер сверху | один источник истины, нет рассинхрона (F4) |
| Надпись «авто-пауза (вне расписания)» | **убрать/заменить** | она дезинформирует (F3) |
| Поле «Сортировка» на видном месте | **отложить** под «…ещё» | админ почти не трогает; шумит в форме |
| Ручной ввод чисел сортировки приоритетов | **заменить** на drag | вспоминание → узнавание (F7) |
| Отдельная кнопка «Сохранить приоритеты» | **слить** в автосейв порядка | меньше «забыл сохранить» |
| Таймзона как свободный текст | **заменить** на select | опечатка ломает расчёт статуса (F10) |

## 11. Быстрые победы (high-impact / low-cost)

1. **Исправить ложную надпись F3** — заменить «авто-пауза (вне расписания)» на корректную причину (лимит). *(S, сразу)*
2. **Заголовок = название точки + статус** (F9) — `AdminShell title={oName(outlet.name)}`, крошка с именем. *(S)*
3. **Добавить переключатель ручной паузы** (F2) — toggle `acceptingOrders` в панель «Состояние». *(S–M)*
4. **Статус-баннер с причиной** (F3/F13) — отдать `statusReason` + `opensAt`/`resetsAt` из `_row`, нарисовать баннер. *(M)*
5. **Подтверждение/валидация лимита** (F1/F10) — numeric-гард + тост-эффект «при 200 точка встанет на паузу». *(S)*
6. **История по-человечески** (F8) — маппинг `type`/`meta`/автор. *(M)*

## 12. Роадмап по фазам

- **Ф1 — «не наврать и не сломать» (P0):** F3 (ложная надпись), F9 (название), F10 (валидация), статус-баннер с причиной (R1), ручная пауза (R2). Это ядро защиты от ошибок.
- **Ф2 — эксплуатация (P1):** карточки формы (R3), Меню-точки единая модель + сводка (R6), История по-человечески (R7), сводка расписания (R8).
- **Ф3 — полировка (P2):** drag-and-drop приоритетов, пресеты паузы «на 1 час/до утра» (`paused_until`), select таймзоны, отложить «Сортировку».
